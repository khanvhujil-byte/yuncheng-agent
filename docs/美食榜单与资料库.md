# 美食榜单与资料库

2026-10-17 实际核验了高德公开页面。公开 REST POI 搜索文档没有看到扫街榜榜单接口或榜单位次字段：

- https://lbs.amap.com/api/webservice/guide/api/search
- https://lbs.amap.com/api/webservice/guide/api/new-poisearch

但是公开网站已有可读取的 HTML 美食榜单：

- https://www.amap.com/ranking/beijing/food
- https://www.amap.com/ranking/hangzhou/food
- https://www.amap.com/robots.txt

页面品牌写“高德扫街榜”，此次实际榜单标题为“北京市2025高德状元榜·美食”和“杭州市2025高德状元榜·美食”。系统保留完整标题与来源，不能把历史榜单宣传为2026实时榜。位次来自该页面 JSON-LD ItemList 的 position，仅表示该标题榜单中的位次，不推导城市综合排名或评分。robots 允许 `/ranking/`，未知爬虫 Crawl-delay 为5秒。

## 已采集的真实数据

独立种子库：`backend/data/food_catalog_seed.sqlite`，北京、杭州各10条。对应可检查来源的 JSON 导出：`outputs/food-ranking-beijing.json`、`outputs/food-ranking-hangzhou.json`。

数据包含 POI ID、店名、原榜单标题、榜内位次、来源URL和采集时间。页面不提供坐标和人均消费，因此这些字段没有伪造。实际规划时通过高德餐饮 POI 查询补齐坐标，只有同一个 POI ID 才能继承榜单信息，名称近似的其他分店不会继承。

## 运行

在 backend 目录使用项目虚拟环境 Python：

```powershell
python scripts/crawl_food.py --url https://www.amap.com/ranking/hangzhou/food --city 杭州 --limit 10 --output ../outputs/food-ranking-hangzhou.json
python scripts/crawl_food.py --import-json ../outputs/food-ranking-beijing.json
```

默认写入项目共享 SQLite 数据库，可用 `--db data/独立文件.sqlite` 指定新的独立库。导入保留原采集时间，不能借导入刷新旧记录。榜单记录30天过期，实际POI候选7天过期。导入命令面向项目维护者，不对普通用户开放任意数据源或数据库路径。

采集限定为 `https://www.amap.com/ranking/<city>/...`，先检查 robots，再间隔至少5秒访问；禁止重定向，限定公开DNS地址，单页最多1MB、最多20条。429/503最多重试一次，尊重 Retry-After，长等待直接结束，避免无界爬取。无需账号、Cookie或高德Key，也不使用未公开登录接口。

## 生成链路

1. `food.collect_food` 先读取未过期餐饮候选和榜单。
2. 最多查询4个未定位榜单店名，再查询1次普通“当地特色美食”，每个查询至多2次安全尝试。
3. 餐饮类型必须包含高德05类，有真实 POI ID 和坐标；原始高德人均消费也只是估算，不能标成实际支付报价。
4. 没有可核验榜单时，明确展示普通高德餐饮推荐。查不到则保留餐饮预算预留，不编造店名。
5. 已生成行程通过最终校验后，`catalog.persist_plan` 按景点、酒店、餐厅稳定ID与工具候选匹配，保存候选原始字段。不会把模型改名、编造实体或未验证报价写成事实。

`place_catalog` 按城市、种类、POI ID去重；`food_ranking` 独立保留榜单证据。两者共享 `store.DB_PATH`，测试会整体切换到临时库。

## 门票和酒店报价

高德 POI 身份数据不等于门票或客房报价。新增 `price_observation` 表与维护者导入命令：

```powershell
python scripts/import_prices.py 已审核的价格观察.json
```

导入文件为 JSON 数组，每条必须提供：`city`、`kind`（attraction/hotel/restaurant）、`poi_id`、`amount`（元）、`unit`（admission/night/person_meal）、`status`（known/estimated）、`source_url`（HTTPS）、带时区的 `observed_at` 和 `expires_at`。门票和房价还必须有 `service_from`、`service_to` 两个适用日期；餐厅人均只能是 estimated。可附 `note` 写明票种、房型和报价口径。维护者应先核对来源、成人/优惠票、房型、人数、税费和日期；程序校验结构和适用条件，不自动宣称网页内容已被人工核实。

导入按城市和 POI ID 精确匹配，不按模糊名字套价。门票适用范围必须覆盖本次旅行全部日期，酒店覆盖所有住宿夜晚。证据过期、日期不符或没导入时保留未知或原有明确估算，不能写零元通过预算。重复使用资料库实体时会清除已经失效的 imported 价格。导入是维护者本地操作，不开放普通用户任意联网抓取和报价写入。

本次没有足够可靠的实时酒店/门票报价来源，因此没有把示例数字灌入真实价格库。离线测试中的价格仅是测试夹具。真实榜单种子库同样不包含虚构消费价格。

## 路程时间

`map_gateway.travel_route` 使用高德步行、驾车、公交对应的正式路线接口返回耗时和距离，MCP模式也经过同一领域契约。没有路线或接口数据不完整时返回未知；骑行尚未接入另一版本的路线接口，返回未知。界面若显示基于距离的时间估计，必须标成估计，不能声称为高德实测。时间均为查询时的预估，不保证未来某日实时拥堵和发车情况。

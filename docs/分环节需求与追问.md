# 分环节需求与追问

用户要求通过统一的 `TripRequest.requirements` 传递，覆盖餐饮、景点、酒店、交通、节奏、天气、预算。相关检索和编排节点读取相应模块，交付、缓存命中、局部修改复用独立校验，不能只在第一次聊天时记住要求。

## 一条完整的数据链路

自然语言 → `conversation.extract` 提取意图和稀疏字段增量 → `conversation.merge` 深层合并 → 必要时追问 → 用户确认 → 检索与筛选 → 编排 → 独立约束校验 → 成功后保存版本。

只改餐饮价格上限，不会恢复餐饮范围的默认值，也不会覆盖酒店偏好。明确换新行程时重新建立本次要求。本次聊天的要求不自动写入长期偏好。

## 什么时候问用户

影响方案的指代不清、相互冲突、取舍未明确，以及缺少证据的硬性要求，应返回 `clarifications`。例如“美食优先，但也别折腾”可以问“全城找店，围绕餐厅安排”还是“仍然优先附近”。不能从“自驾”直接推断“不限距离”，也不能把“轻松点”擅自换算成一个分钟数。

每轮最多新增三个关键问题，可提供二至四个有明确字段效果的选项；需要具体日期或名称时允许自由回答。服务器保存问题编号及选项对应的字段增量，浏览器只获得选项文字。选项不预选；点击后才应用服务器保存的增量。问题刷新后仍保留，回答一个问题不清除其他问题。

自然语言回答由模型声明已经解决的具体问题编号，服务器检查编号存在。无关补充不会自动清空追问。未回答的问题阻止生成和局部编辑；选择选项本身不调用规划图。重复提交使用原有 request_id、revision 和操作记录保证幂等，陈旧选项不能更新会话。

## 已支持的可执行要求

| 模块 | 已接入的结构化规则 |
| --- | --- |
| 餐饮 | 检索关键词、餐厅排除名单、附近或全城、景点优先或美食优先、每人每餐参考价上限 |
| 景点 | 检索关键词、排除名单、每日数量上限 |
| 酒店 | 检索关键词、排除名单、每晚参考房价上限 |
| 交通 | 现有交通方式、单段时间上限、是否接受明确标记的估算路线 |
| 节奏 | 每日总时长上限、游玩加通勤时长上限 |
| 天气 | 雨天避免户外，天气未知时不能证明满足 |
| 预算 | 现有总预算、门票/住宿/餐饮/交通核算；分配偏好传入编排 |

交通硬时间限制需要实际查询到的路线时间，不能用估算冒充满足。价格约束按有来源的参考价判断，不保证最终成交价。下雨时室内地点使用名称/分类的保守规则识别，并非完整的场馆设施数据。

美食优先时，模型必须从真实候选中选择餐厅编号，再安排景点。全城模式取消固定的就近优先规则，但仍受候选池、请求次数和最终路线可行性检查限制，不保证求得全城最优路线。餐饮每次最多四个指定/榜单查询加一个通用查询，超过四个指定关键词会提示尚未逐项检索。

## 偏好、硬规则与证据

各模块 `instructions` 保存文字偏好并传给相关节点。文字偏好本身不等于代码已经验证。前端的模块文字框是偏好输入；明确限制可使用数值控件，复杂要求通过聊天提取、追问。

过敏安全、无障碍设施、实时营业与预约资格等，不能由模型或 POI 名称保证。自然语言提取应将需要证据的硬要求放入 `unverified` 并追问；该字段非空时阻止规划。用户补充资料后仍需要相应验证能力，不能仅清空字段就宣称资料已核实。明确放宽要求的选项应说明放宽的内容。

任意自然语言的正确识别仍依赖模型，离线测试未证明真实模型能识别所有要求。当前也不支持任意出发时间、零景点纯餐饮行程或所有跨城市自驾需求；遇到这些需求应说明能力边界。

## 修改与验证

修改全局要求会使旧请求缓存失效，候选复用也检查 requirements，避免使用旧条件的结果。酒店、某餐、某个景点和某一天的局部修改使用原有独立路径；候选先按价格和排除规则筛选，提交前重算依赖路线、日程及预算并执行同一需求校验。失败保留原行程和具体错误。

主要代码：`models/requirements.py`、`services/requirements.py`、`services/conversation.py`、`services/dialog_store.py`、`services/partial_edit.py`，以及前端 `RequirementPanel.vue` 和 `ChatView.vue`。

`tests/test_requirements.py` 覆盖追问持久化、选择隔离、稀疏合并、隐私、缓存与需求审计；`test_integrated_e2e.py` 使用真实规划图和工具运行时，替换外部模型/地图调用验证有界重试；`test_partial_edit.py` 验证局部修改不能绕过约束。`scripts/eval_integrated.py` 导出离线逐例结果，这些是正确性回归，不是线上成功率或模型质量评测。

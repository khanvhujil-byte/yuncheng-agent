# FlyAI 旅游平台只读接入 PRD

日期：2026-10-20；状态：本期只读接入已实施并验证；容器构建待 Docker 服务可用后验证。

## 问题与目标

地图 POI 主要提供地点与坐标，不能代替真实旅游商品报价。用户已配置 FlyAI Key，官方客户端实测可以查询飞猪景点。直接用 Bearer 连接 MCP 曾返回 401，官方客户端带签名的请求成功，因此保留官方客户端，不自行复制签名算法。

目标：提供可复现、可关闭、可测试的景点/门票、酒店、机票、火车票查询；把门票商品证据接入现有票价补全链路，供用户检查商品与来源。行程编排仍由统一 Agent 决策，确定性代码约束地点身份和价格口径。

## 本期范围

1. 锁定官方 CLI 1.0.16，用带校验的安装脚本安装至 backend/.runtime；运行时不执行 npx、不下载依赖、不向模型开放任意命令。
2. 配置统一由 config.py 读取，支持 FLYAI_API_KEY、开关、超时、请求间隔；Key 仅通过子进程环境传入，接口不返回 Key。
3. 独立只读适配器：允许景点、酒店、航班、列车四种查询，参数白名单、日期校验、超时、共享限流、短期缓存、结构化错误。超时不自动重复付费查询。
4. 登录保护的 POST 查询 API，保留平台商品 ID、报价、币种、计价单位、观测时间、日期、跳转链接和来源。不得将搜索价描述为已确认库存或已预订价格。
5. 景点票价补全在缺少内部可靠价格时查询 FlyAI；同名精确匹配且票种明确时作为商品参考证据；子景点、套餐、儿童票、无日期或不明确的起价不直接当作成人日常门票。无法确认的仍走原官网检索/估算链路，不能把查不到价格当免费。
6. 酒店、航班、火车票本期交付查询能力；住宿全量合池、出发地表单、跨城交通进入总预算与前端预订交互另立 PRD，本期不宣称完成一站式预订。

## 成功标准

- 当前 Key 可通过后端适配器查询真实景点；至少再验证一项酒店或交通查询；未验证项目明确标注。
- 四类接口有契约测试，覆盖参数错误、无结果、格式异常、无效凭据、429、超时、缓存及登录鉴权。
- 票价匹配测试覆盖故宫与珍宝馆、成人/儿童/套餐、无价格及无报价日期；不得相互套价。
- 凭据不进入响应、日志、命令行参数、版本库；禁用或平台异常不破坏原规划链路。
- 票价相关既有回归通过；原有大量未提交更改保留。

## 限制条件

- 平台可能不返回价格，不能保证所有 POI 都有门票商品。无商品价格时沿用现有带来源的票价查证/估算，不伪造平台报价。
- search-poi 当前无结构化游玩日期参数；报价不等于目标游玩日可用票，普通门票预算与商品报价分开。
- 酒店价格为搜索参考，不能推断人数、房型、税费、取消规则；交通价格不等于出票承诺。
- 实测查询涉及真实配额，仅做少量查询；不承诺未核验的免费额度和 SLA。
- 限流与缓存是单进程能力；多副本部署需共享限流/缓存。
- 官方 CLI 需要 Node.js >=18，安装依赖需要联网；运行时需要平台网络可达。

## 开发计划

1. PRD 与适配边界；2. 固定版本安装、配置与只读适配；3. 登录查询接口及门票证据接入；4. 离线测试与少量真实查询；5. 记录配置、使用方式及验证结果。

## 非目标

不下单、不付款、不抢票，不安装全局 CLI；不更换现有高德地图 MCP，不改动已完成的云程主题。本期不承诺项目整体已达到生产上线标准。

## 本期验收结果

景点、酒店、机票、火车票各一次真实查询成功；后端全量离线回归通过，最终专项回归136项通过；静态检查通过。原后端空闲时重载，/health 正常，五个旅游接口在 OpenAPI 可见，未登录访问返回401。Docker 客户端存在但 Linux engine 未运行，镜像构建尚未验证。详细配置、价格口径与样例见《FlyAI接入与验证-20261020.md》。

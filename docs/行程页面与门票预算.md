# 行程页面与门票预算

页面顺序为目的地、住宿/天气/预算概览、逐日行程。预算中的门票逐项展开，其他费用明细和补充说明收在可展开区域。

每天先显示地图，再按后端计算的游览顺序展示景点和三餐。独立时间表与逐段路程列表已移除；到达上一站的交通方式、耗时与距离直接嵌入地点卡片，返程放在最后一站。建议游玩时长仍显示在景点中。后台保留时间安排用于舒适度和预算校验。

地图使用同一份地点顺序，包含餐厅和每天出发的酒店。无底图时使用明确标注的点位示意图，连线不冒充真实道路。

## 门票取价

1. 优先使用本地未过期、适用出行日期的价格证据。
2. 对已维护的官网规则按城市及景点名称精确匹配，采集成人基础门票。当前已实测两个站点：
   - 故宫博物院 `https://www.dpm.org.cn/Visit.html`：旺季60元、淡季40元，按实际出行月份匹配；不把珍宝馆、钟表馆10元误作大门票。
   - 成都大熊猫繁育研究基地 `https://www.panda.org.cn/cn/service/ticket/`：成人入园55元；不混用儿童、学生等优惠票，不包含观光车等服务。
3. 未适配的景点、网页变更或访问失败时，暂按每处100元做门票预算预留。显示“预留/待核实”，来源为 `static_estimate`，计入估算费用及预算上限复核，不声称是官网报价。已核实免费项目保留0元。

官网页面的成功快照缓存24小时，失败冷却15分钟；最多查询两个来源，每次请求超时4秒。日期超过90天时不把当前政策当成已核实的远期报价。读取快照不会延长原采集时间。

每份官网价格保存来源URL、原文片段、观察时间、失效时间和适用日期，沿用现有价格观察表。只解析已维护站点的明确成人票规则；没有声称支持所有城市或任意官网，也没有用模型自行填充真实票价。扩大覆盖需在 `ticket_pricing.SOURCES` 增加经核验的来源与解析规则。

旧行程仅在展示时补齐明确标注的门票预留，重新计算参考总额和每日小计，不覆盖已保存版本，也不修改后端原始成功/失败结论。重新生成或局部修改后，由后端统一核算。

配置项见 `backend/.env.example`：`OFFICIAL_TICKET_LOOKUP_ENABLED`、`TICKET_BUDGET_RESERVE_ENABLED`、`TICKET_BUDGET_RESERVE_AMOUNT`。

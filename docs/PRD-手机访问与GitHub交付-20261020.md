# 云程：表单对齐、手机访问与GitHub交付

日期：2026-10-20。用户要求修复出发城市和城际交通控件对齐，说明手机部署，并准备上传GitHub。

## 问题与范围

1. 出发城市的“选填”作为独立flex子项占一行，导致相邻输入框错位。将说明合入同一标题行，并检查首页与对话页的桌面、手机布局。
2. 前端默认请求127.0.0.1:8000，在手机上会指向手机自身；生产空API地址也被回退为本机地址。统一使用同源API默认值，并在Vite增加/api和/health代理，保留显式后端地址覆盖能力。
3. 提供同一Wi-Fi手机体验入口，以及生产HTTPS网站部署步骤。手机浏览器访问服务即可，无需原生安装包。公网发布需部署服务器和域名，GitHub只保存代码，不能代替Python/Java后端运行。
4. 清理Git可提交范围，检查环境文件、凭据、数据库和日志，准备本地版本；远程仓库目标与可见性由用户明确后再上传，不默认公开源码。

## 成功标准

- 1440与390宽度下两个控件顶部差不超过1px，无横向溢出，表单保存与查价流程可用。
- 使用当前页面主机名访问同源/api，局域网访问无需把后端暴露到局域网；健康检查代理正常，生产空地址不会回落到手机localhost。
- 构建、现有前端回归和实际浏览器验证通过；说明Windows防火墙和同网段限制。
- GitHub上传不包含真实密钥、会话数据库、日志或依赖产物；不覆盖既有未提交工作，不强制推送。

## 限制与计划

本次不制作Android/iOS安装包，不购买云服务或默认公开开发端口，不自动关闭防火墙。实现顺序：布局修复→API地址与代理→浏览器及手机访问核验→Git提交范围与凭据检查→提供部署说明→按已确认的GitHub目标上传。

# FlyAI 接入与配置

本期：官方 CLI 1.0.16 只读查询，提供景点/门票商品、酒店、机票、火车票。酒店与城际交通已接到前端表单、独立查价和统一编排候选池；机场/车站接驳、首末日时间、同行人数与房间数进入预算和交付复核。没有下单与支付能力。

## 安装与 Key

在 backend 目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\install_flyai.py
```

脚本下载固定版本官方 npm 包、校验 SHA512，仅提取固定文件，不执行 npm 生命周期脚本。需要 Node.js >=18。运行时不会联网安装客户端，缺少客户端会返回 FLYAI_RUNTIME_MISSING。backend/.runtime 已忽略，不入 Git。

Key 由后端 config.py 读取，使用 FLYAI_API_KEY。当前 Windows 支持读取用户环境变量中的这一个 Key，无需复制进前端。进程环境和 backend/.env 的显式配置优先；如果 .env 中存在空的 FLYAI_API_KEY=，它会覆盖用户环境变量，应删除空配置或填入有效 Key。修改配置后重启后端。

Linux/容器部署在服务端环境注入 FLYAI_API_KEY；Windows 用户环境变量不会自动进入容器。Dockerfile 已加入 Node 运行时和带校验的安装步骤，镜像构建需要访问 npm registry；本次未执行 Docker 镜像构建验证。

可用开关：FLYAI_ENABLED=false 完全关闭；FLYAI_TIMEOUT_SECONDS 默认12；FLYAI_REQUEST_INTERVAL_SECONDS 默认1；FLYAI_CACHE_TTL_SECONDS 默认120。自动门票补充每次运行最多2个新查询，总等待预算5秒，失败不在同一运行中重复查询该地点和日期。

自动住宿/城际采集各受 FLYAI_PLANNING_BUDGET_SECONDS（默认12秒）约束，共享上游调用节奏；酒店地图核验最多 FLYAI_HOTEL_MATCH_LIMIT（默认4）个商品。超时或限流后保留结构化原因，不无限重试。接驳站点每个所选方向最多核验一次，重排复用核验结果。

## 接口

API 前缀 /api/travel。全部要求有效登录会话 X-Session-Token，并沿用现有 API 访问控制、应用限流。返回 outcome（status/error_code/retryable/message/stats）及 items，错误原因保持结构化，不从中文描述推断是否重试。不要只用 HTTP 200 判断查询成功，需检查 outcome.status。

| 方法 | 路径 | 请求内容 |
| --- | --- | --- |
| GET | /status | 配置和客户端是否就绪；不执行付费查询；不返回凭据 |
| POST | /attractions | city，keyword（可选） |
| POST | /hotels | city，check_in，check_out，keyword/max_price/sort（可选） |
| POST | /flights | origin，destination，departure_date，max_price（可选） |
| POST | /trains | origin，destination，departure_date，max_price（可选） |

日期格式 YYYY-MM-DD，酒店/交通要求未来日期，酒店最多30晚；城市使用中文。可通过运行中后端 /docs 的「旅游平台只读查询」分组查看完整参数。

酒店查询示例（日期应替换为未来日期）：

```json
{"city":"杭州","keyword":"西湖","check_in":"2026-10-27","check_out":"2026-10-28","max_price":600}
```

## 价格及规划口径

- 景点的平台 ID、商品 ID 与高德 POI ID 分开保存。故宫珍宝馆的商品不能套给故宫博物院。
- 搜索商品价不等于日常挂牌价或确认库存；无金额、起价、范围、其他币种不会解析成零。
- 酒店 amount 的单位为 room_night_reference，是每房每晚参考价，不能当多晚总价或推断房型、入住人数、税费。
- 交通保留班次、站点、时间、席别；优先读取adultPrice，缺失时兼容真实响应的price并标注搜索展示参考。缺少可解析金额时amount=null，不猜测票价；不能把展示价宣称为确认的成人含税成交价。
- 已有内部可靠票价优先，其次维护的官网适配，再查 FlyAI，再走公开官网搜索，最终使用明确标注的日常门票模型估算/预算预留。
- 自动引用平台门票须名称和地址精确一致、唯一明确的成人基础票、报价日与游玩日相同、存在商品身份和 HTTPS 来源；按 estimated 商品预算参考记录，绝不标 known 日常挂牌价。当前 search-poi 没有游玩日期参数，实际经常不满足这些条件；这种情况只记录商品证据并继续查日常价格。
- 成功、失败、耗时、缓存与实际客户端调用均进入现有门票工具 trace；无日期、子景点等无法绑定的原因也有记录。报价缓存不会因为再次读取而延长有效期。

## 端到端整合

需求与范围见 [交通住宿整合PRD](PRD-交通住宿端到端整合-20261020.md)。

- 首页与「我的旅程」可设置origin_city、intercity_mode（none/train/flight/auto）、return_trip、adult_count、room_count。目的地仍为city，日期为目的地游玩日期。默认自行安排城际交通、一位成人、一间房。
- 统一编排Agent同时选择景点、餐厅、逐晚住宿与transport_choices中的去返程候选ID。站点、金额、日期和坐标由代码回填；按所选班次生成餐次义务、出站与候车预留，首末日路线连接到地图核验站点。
- 酒店名称可有供应商别名，但必须匹配具体地址、兼容楼层、名称主体且唯一命中；品牌相同不足以套价。同楼不同楼层、不同门牌、不同酒店拒绝合并。地图坐标仍是路线事实来源。
- 房价保留覆盖日期、观测时间、来源和失效时间。更换日期、局部换酒店、确认预览、历史复用均重新检查；过期金额不继续作为有效报价。全程搜索参考不保证各晚同价或特定房型/入住人数。
- 门票、餐饮、城际交通按成人数汇总，住宿按房间数；市内自驾按一辆共享车辆预留。日小计、类别小计和总计对账。未知班次、票价及未确认机票税费单列，不按免费判预算通过。
- 含城际交通的请求不复用完整历史行程缓存；餐饮修复保留已选班次，局部修改不自动再搜交通。无法赶上班次或缺少接驳坐标时不能宣称规划成功。

最后一次真实酒店合并查询耗时8.85秒，匹配2家地图酒店，取得86元和161元/房晚搜索参考；这是当次日期查询观察，不是价格承诺。上海→杭州、杭州→上海实测各取得3个有效直达候选、核验杭州东站坐标并通过交通独立审计。真实响应price字段解析后可取得57/65元等展示参考，仍以平台实际预订为准。

只支持中国内地成人直达、单目的地单程/往返参考规划；暂不安排中转联程、多城市、儿童/婴儿或出票支付。平台空结果、无法唯一对应地点时保留原因，不能承诺全城市与全日期覆盖。容器构建仍未验证。

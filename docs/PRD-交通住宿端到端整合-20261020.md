# 云程：交通与真实住宿端到端整合

日期：2026-10-20。用户授权：把已验证的 FlyAI 查询加入前端及自动编排，并修复关联链路。

## 问题

当前飞猪查询与生成主链分离；酒店仍主要使用预算预留，缺少出发地、往返班次、人数/房间数和跨城预算。若只展示查询卡片，交通时间不会限制首末日，酒店日期变化可能继续复用旧价，缓存和局部修改也可能绕过复核。

## 本期范围

1. 新增可选出发城市、城际方式（不安排/火车/飞机/自动比较）、往返方式、成人数、房间数。保留单人一房默认；选择城际交通须给出发地。
2. FlyAI酒店候选与本地/地图候选合池，保留平台身份、坐标来源、报价日期和来源链接。报价只用于查询覆盖的入住日期，逐晚费用按房间数计算；过期或不适用日期明确标未知，原有非平台候选可保留清楚标注的预算预留。平台没有价格或坐标时不能伪装成已核验可订酒店。
3. 有界采集去程/返程班次，统一编排Agent从真实候选ID中选择，与景点、餐饮、每晚住宿一起考虑。代码回填班次、日期、费用、车站/机场、接驳端点，不接受模型编造的交通事实。
4. 交通接入首末日时间窗口：到站/落地后的出站预留、发车/起飞前的候车预留、当地接驳纳入路线。夜间/跨日交通明确限制，无可用班次给具体原因，不能把城际交通消失掉。
5. 总预算含成人门票、餐饮、市内交通、跨城票价及房间费；未知票价保持未知，不按免费处理，不把单人票价直接当多人总额。
6. 首页和对话信息表单支持上述输入；行程前部展示去返程、来源、参考票价、日期和候车说明；住宿显示报价/预留差异及平台链接；支持登录后独立查询酒店/交通，选择交通偏好后重新编排而非覆盖原有已确认结果。
7. 对话槽位、缓存签名、断点状态、局部修改、交付复核一起适配。交通/平台报价不能不加复核地跨日期复用；替换酒店重新算日期、路线、房间费，保留其他模块。

## 成功标准

- 不安排城际交通时保持原规划可用；新字段端到端进入后端，不只停留在表单。
- 所有交通必须来自当前事实候选；错方向、错日期、到离时间不匹配、缺返程、价格过期有明确检查。
- 城际选择影响餐次、可用游玩时段、车站接驳和预算；一日游不会选择到达晚于返程的组合。
- 酒店成人/房间计价不混用，预算分类、逐项之和、逐日小计与总额对账。
- 相关离线测试、完整后端回归、前端测试/构建、桌面/手机浏览器流程通过；真实查询限量验证，不反复消耗配额。

## 限制

只查询不下单。平台搜索价不保证库存、税费、席别剩余量、房间人数、取消规则；机票税费未知时明确说明。城际仅处理中国内地单目的地往返/单程成人参考，不扩展多城市联程、儿童/婴儿、国际签证或复杂铁路售票规则。不能因限流无限重试；新增采集有调用/时间预算。机场车站坐标需地图核验，不能直接混用未知坐标系的酒店坐标。无数据时保留可用行程和原因，不伪造成功。

## 开发计划

契约与状态 → 酒店合池及报价适用规则 → 交通采集/统一选择/时间接驳 → 预算及交付审计 → 表单与展示/平台查询 → 缓存局部修改一致性 → 离线及浏览器验证 → 本地重载和交付说明。

## 实施记录

已实现上述主链与表单、交通摘要和独立查价。额外修复真实返回使用price而非adultPrice造成票价丢失、酒店跨平台别名与楼层地址匹配、餐次补丁丢失班次、异步缓存绕过交通有效期、局部换酒店丢失报价、多人自驾重复收取整车预留等问题。

离线端到端场景覆盖统一编排ID回填、夜间到达、早班车接驳、远郊末晚酒店赶不上车的拒绝交付、多人预算和最终审计。浏览器使用隔离测试数据，在1440和390宽度验证输入、类型正确的保存、独立查询成功/空结果/错误及过期界面结果清除；未使用浏览器fixture结果冒充真实平台报价。

验收完成：后端全量1145项、最终预算专项123项、前端14项通过，生产构建和桌面/手机浏览器检查通过；另有真实双人城际规划通过交付。详细证据、限制和价格口径见 [FlyAI接入与验证](FlyAI接入与验证-20261020.md)。本地服务已重载，容器发布不属于本次已验证结果。

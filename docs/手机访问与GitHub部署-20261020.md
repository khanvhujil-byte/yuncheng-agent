# 云程：手机访问、正式部署与 GitHub 上传

日期：2026-10-20。

## 一、现在用手机体验

这是浏览器网站，手机无需安装 APK。电脑和手机连接同一 Wi-Fi，电脑保持开机。

电脑后端照常启动，只需监听 `127.0.0.1:8000`；前端进入 `frontend` 运行：

```powershell
npm run dev:lan
```

手机在浏览器打开 `http://电脑的局域网IPv4:5173/chat`。例如当前检查到的无线网卡地址是 `10.161.97.109`，则使用 `http://10.161.97.109:5173/chat`。这个 IP 可能随网络变化，用 `ipconfig` 查看 WLAN 的 IPv4，勿使用 VMware/WSL 虚拟网卡地址。

前端 `/api`、`/health` 请求由 Vite 代理到电脑后端，`/community-api` 仍转发 Java 服务。因此手机不需要访问 8000、3306、6379。`frontend/.env.local` 中的 `VITE_API_BASE_URL` 应留空；如曾填写 `127.0.0.1` 或 `localhost`，清除这个覆盖值后重启 Vite。手机上的 loopback 指向手机自己。

如果打不开，先在电脑访问同一个局域网 URL，确认 Vite 终端没有端口占用错误；再确认手机未使用移动数据/VPN、路由器没有 AP 隔离。Windows 防火墙如拦截，只允许该 Node 程序在可信网络接收 5173/TCP 的局域网连接，不要关闭整个防火墙。不要将 Vite 开发端口做公网端口转发。

这只是同网体验：电脑关机就无法访问，也不能当作已经完成公网部署。实际手机端的防火墙、Wi-Fi 隔离仍需用手机验证。

## 二、正式上线，让手机随时访问

建议部署为 HTTPS 网站：Linux 云服务器运行项目的 Docker Compose，域名指向服务器。手机访问域名即可。GitHub 保存代码；单独发布前端静态文件不能运行本项目的 Python、Java、MySQL、Redis 服务。

服务器安装 Docker Engine 与 Compose，拉取代码后：

```bash
cp .env.production.example .env.production
cp backend/.env.example backend/.env
# 编辑 .env.production，填写两个不同的强数据库密码。
# 编辑 backend/.env，配置模型、高德等后端凭据。
# 启用平台酒店/机票/火车票时同时配置 FLYAI_API_KEY。
# 密钥不放在 git 命令、README、前端 VITE_* 或浏览器请求参数里。
docker compose --env-file .env.production -f docker-compose.production.yml config --quiet
docker compose --env-file .env.production -f docker-compose.production.yml up -d --build
docker compose --env-file .env.production -f docker-compose.production.yml ps
curl --fail http://127.0.0.1:8080/health
```

`FLYAI_API_KEY` 在开发电脑上的 Windows 用户环境变量，不会自动出现在 Linux 服务器/容器中；必须在服务器后端环境重新配置。不要把本地账号和会话数据库随源码上传。若需要迁移真实账号，单独做受控的数据备份与迁移。

本仓库生产入口绑定在服务器 `127.0.0.1:8080`，不是公网监听。服务器用已有的 Nginx 或 Caddy 在 80/443 终止 HTTPS，并转发到 `127.0.0.1:8080`。公网只开放必要的 80/443，数据库、Redis 和 Python 不直接开放。若外层代理也是容器，须把它连接到应用网络，不能把容器内的 127.0.0.1 当作宿主机。

以下为宿主机 Nginx 的 HTTPS 站点片段，替换域名和证书路径；80 端口应配置跳转到 HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name travel.example.com;
    ssl_certificate /your/cert/fullchain.pem;
    ssl_certificate_key /your/cert/privkey.pem;
    client_max_body_size 2m;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }
}
```

外层关闭缓冲是为了让 SSE 进度事件及时送达。正式上线前按《上线准备与验收》验证登录、生成、流式进度、历史行程、社区、预算与失败提示，并备份三个持久化数据卷。不要运行 `docker compose down -v` 来做普通更新，否则会删除数据卷。

当前生产 Docker 构建默认没有浏览器地图 Key，会采用页面现有的 SVG 地图降级。需要真实浏览器地图时，应单独配置受限的浏览器地图 Key，并明确提供给前端构建；后端服务密钥不可复用成公开前端 Key。`VITE_API_BASE_URL` 默认留空，由内置 Nginx 代理 API。

本次没有购买服务器、配置域名或宣称已公网部署；真实部署仍需要目标服务器访问权限与域名。

## 三、上传 GitHub

当前项目已有 Git 历史，保留现有历史和 LICENSE。先确认仓库地址与可见性，个人作品初次保存建议选择私有仓库；准备公开后再复查数据与许可证。

在 GitHub 新建空仓库，不预生成 README、LICENSE 或 .gitignore。项目已存在这些文件。然后在项目根目录执行：

```powershell
git status --short
git remote -v
# 待提交文件应先经过检查；只提交源代码、测试、文档、空值配置模板与必要资源。
# 本地版本提交完成后，使用自己实际创建的仓库地址：
git remote add origin https://github.com/YOUR_ACCOUNT/yuncheng-agent.git
git push -u origin master
```

当前分支名是 `master`，不强制改名、不强推。已有 `origin` 时先核对地址，不直接覆盖。若远端非空，先读取远端历史并选择保留双方历史的合并方式，不用 `--force` 绕过冲突。

Git 提示登录时使用系统 Git Credential Manager 的浏览器登录，不把 PAT/API Key 发到聊天里或写进仓库 URL。若偏好图形操作，GitHub Desktop 的 File → Add local repository 可选此项目，再登录并 Publish repository。

`.gitignore` 已覆盖真实 `.env*`、数据库、日志、证书私钥、依赖目录与 FlyAI 本地运行时；`.env.example` 等空模板保留。忽略规则不能撤回历史中已提交的密钥，上传前仍应检查当前文件和 Git 历史。不要用“上传整个文件夹”的方式把运行目录一起带上去。

GitHub 地址、可见性或登录未完成时，只能完成本地准备，不能声称已经上传。
